# Decisions

Decisions about how this repository is built. How the machine is operated belongs in `CLAUDE.md`
or a skill, and machine facts (host names, private paths, hardware detail) never enter this file:
`.githooks/pre-commit` runs `guard-private.sh` over every staged file and fails on them.

A row enters the table when it passes both filters, in order.

1. No owning surface. A rule some surface already owns goes there: `CLAUDE.md` for an invariant
   of this machine or the command for a question, a skill for its own domain, chezmoi for what
   chezmoi already enforces. `Why rejected` records which surface was examined and why it does
   not reach.
2. Two incidents, or a structural choice that shapes the repository from the start.

A row leaves when a surface can hold its rule.

| # | Date | Decision | Alternative | Why rejected | Consequence |
|---|---|---|---|---|---|
| 1 | 2026-09-20 | chezmoi copies files into `$HOME`; `sourceDir` is this repository. | symlinks, GNU stow | a symlinked config that an application rewrites in place silently edits the repository, and `$HOME` breaks when the clone moves. | A file edited in `$HOME` is lost on the next `chezmoi apply` unless `chezmoi re-add` runs first. Templates and per-machine prompts work, which symlinks cannot do. |
| 2 | 2026-09-20 | Only the delta over Omarchy's defaults is versioned. | a full capture of `~/.config` | every `omarchy update` then lands as a diff to review, and the repository owns files it never chose to change. | Omarchy owns the baseline and updates it; a file enters this repository only when its content differs on purpose. A default that changes upstream arrives without a merge. |
| 3 | 2026-09-20 | Secrets live in the system keyring; templates render them at apply time. | `age` or `sops` | the ciphertext sits in git, so a leaked key exposes history, and a second secret store has to be provisioned before the first apply. | `bootstrap.sh` asks once per machine and writes the keyring. A clone without the keyring fails at `chezmoi apply` with `secret not found in keyring`, so `bootstrap.sh` has to run before the first apply. |
| 4 | 2026-09-22 | The `Edit\|Write` branch of `guard-private` stays as it is, reporting nothing. Measured that day: it runs as `PostToolUse`, so the file is already written; `\|\| true` forces exit 0; the path is relative where the `Bash` branch runs `cd "$CLAUDE_PROJECT_DIR"` first; and it never redirects to stderr where the `Bash` branch uses `>&2`. A private name reached a document through it and only `.githooks/pre-commit` caught it. | move it to `PreToolUse` with exit 2, or fix the four defects in place | four hook patches landed the same day, three of them on the lexical test in `gate-skill-writes` and one deleting a hook that never fired. The user stopped the fifth. A fix touching only the first three defects still reports nothing, because stdout from a `PostToolUse` at exit 0 never reaches the agent, which is what makes this a design question rather than a patch. | A write carrying a login name, a home path or a private project name is not stopped and not announced. `.githooks/pre-commit` is the only gate, so nothing reaches history and a session can work for a while on text that will fail at commit. Run `./.claude/hooks/guard-private.sh <file>` by hand before closing a document. |
| 5 | 2026-09-23 | Verify a claim about code by reading the path a case takes before running it, not by comparing outputs. A case that never reaches the code under test agrees with every version of it. | trust a table of inputs and outputs | an output table records what happened and not why, so a case that could never have differed reads as a case that agreed. Two shapes, four times on 2026-09-23. A branch above the one under test decides the case: `stop_hook_active` read only to return False, so a misspelt key blocked exactly as a correct one does; `verdict`'s asymmetry found by reading branches after an output table showed three identical results; the `god` flag short-circuiting the recipient test, which made `w1T:p1` read as confirming a fix it could not discriminate. An entry point bypasses it entirely: `attended` was verified through `ask-gate.py`, which reads the registry file directly, so `read()` and `resolve()` were never on the path and no case written that way could have found them omitting the field. | A count of confirming cases is inflated by every case something above decided. Reading the path before running anything is what separates them, and a fixture whose inputs differ while its outputs do not is the signature of a case that never arrived rather than a finding. Verifying the consumer is not verifying the feature. |
| 6 | 2026-09-23 | After fixing a claim, search for what else states it in other words. A grep closes a class of code paths and never a class of claims. | sweep the identifier and consider the class closed | a claim restated without its identifier survives the sweep that fixed it: the role-derivation class was swept on `HERDR_REPORTS_TO` on 2026-09-23 and three sentences in `README.md` survived, one of them naming no identifier at all. `skill-growth` routes this to `adr.md` and its two-incident filter is not met; the user admitted it on one sighting rather than hold it. | A sweep by identifier reports a class closed while the prose that teaches the same claim still stands. What closes it is searching for what else tells a reader the same thing, which nothing mechanical does. |
