# Decisions (dotfiles)

Use this file for lightweight Architecture Decision Records (ADRs).
Record meaningful technical or process decisions that affect maintainability, delivery speed, or system behavior.

## ADR guidance

- Write one entry per decision.
- Keep entries concise and date-stamped.
- Capture context before the decision so readers understand tradeoffs.
- If a decision changes, add a new entry and mark the old one as superseded.

Suggested status values: `proposed`, `accepted`, `superseded`.

## ADR template

### YYYY-MM-DD: <Decision title>

Status: <proposed|accepted|superseded>

Context:
- <what problem or constraint are we solving?>

Decision:
- <what did we choose?>

Consequences:
- <benefits>
- <costs or risks>

Alternatives considered:
- <option A and why not selected>
- <option B and why not selected>
